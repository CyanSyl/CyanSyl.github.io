# 个人博客设计文档

- 日期：2026-10-19
- 状态：已与需求方确认
- 周期：两周（含学习）

## 1. 背景与目标

开发一个综合型个人博客。开发者前端零基础（会一点 HTML/CSS），有后端学习经验，希望在两周内以前端实践的方式完成博客并学到扎实的前端基础。

**目标：**

- 上线一个包含文章、项目展示、关于我的个人博客
- 过程中掌握 HTML/CSS/JS 基础与 Astro 组件化思想
- 代码全部自己编写，不依赖现成主题，保证后期"坏了修得了"

**非目标（YAGNI）：**

- 不做后端、数据库、在线写作后台
- 不使用 Tailwind 等 CSS 框架（用纯 CSS 打基础）
- 评论、RSS、暗色模式等作为加分项，视进度而定

## 2. 技术选型

| 项目      | 选择                                                       | 理由                               |
| ------- | -------------------------------------------------------- | -------------------------------- |
| 框架      | Astro（静态站点生成）                                            | 内容驱动、Markdown 一等支持、教程完善、可按需渐进加交互 |
| 样式      | 纯 CSS（全局样式 + 组件 scoped 样式 + CSS 变量）                      | 零基础应打 CSS 基本功；博客样式量纯 CSS 足够      |
| 内容管理    | Astro Content Collections（Markdown + zod 校验 frontmatter） | 类似后端 DTO 校验，元信息错误在构建期暴露          |
| 部署      | GitHub Pages + GitHub Actions                            | 免费零运维；产物为纯 HTML，日后迁移国内成本低（仅备案耗时） |
| 评论（加分项） | giscus（基于 GitHub Discussions）                            | 零后端成本，接入简单                       |

数据流向：`Markdown 文件 → Astro 构建 → 静态 HTML → GitHub Pages`。

## 3. 页面结构

| 路由 | 内容 |
|---|---|
| `/` | 首页：首屏为主题大图 Hero 区（可配一句标语/署名），向下滚动展示最新 3-5 篇文章 + 精选项目入口；无文字自我介绍 |
| `/blog` | 文章列表，按日期倒序，可按标签筛选 |
| `/blog/[slug]` | 文章详情页 |
| `/projects` | 项目展示卡片（名称、简介、技术栈、链接），数据来自结构化数据文件，改项目 = 改数据 |
| `/about` | 关于我：完整个人介绍（经历、技能、联系方式） |

导航栏：`首页 / 文章 / 项目 / 关于我`。

Hero 区实现要点：首屏占满视口高度；主题图需准备横版大图，做响应式适配与压缩以控制加载速度。

## 4. 组件设计

每个组件职责单一、可独立理解与测试：

- `BaseLayout.astro` —— 全站外壳：导航栏 + 页脚 + `<head>`，所有页面复用
- `BlogPost.astro` —— 文章详情页布局：标题、日期、标签 + 正文插槽
- `PostCard.astro` —— 文章列表中的单篇卡片
- `ProjectCard.astro` —— 项目卡片

## 5. 内容模型

文章 frontmatter（zod 校验）：

- `title`：标题（必填）
- `date`：发布日期（必填，日期格式）
- `tags`：标签数组
- `description`：摘要（用于列表页与 SEO）
- `draft`：草稿标记（草稿不发布）

项目数据：结构化数据文件（名称、简介、技术栈、链接、是否精选）。

## 6. 质量保障

静态博客无运行时错误处理需求，质量靠三点：

- frontmatter 的 zod 校验（构建期报错）
- `astro check` 类型检查
- 开发时 `npm run dev` 预览；合并/部署前 `npm run build` 确认可构建

## 7. 部署

- push 到 GitHub 仓库 → GitHub Actions 自动 `astro build` → 发布到 GitHub Pages
- 暂不绑定自定义域名；日后迁移国内仅需更换托管目标 + 域名解析 + ICP 备案

## 8. 加分项（第 12-14 天按进度选做）

- giscus 评论
- 暗色模式（CSS 变量 + `prefers-color-scheme`）
- RSS 订阅
- SEO 优化（meta、sitemap）

## 9. 两周计划（学习 + 开发混合）

策略：压缩官方教程而非跳过——第 1 天快速过教程前半部分拿到"最小词汇量"，之后从零搭建自己的博客，教程后半部分当工具书按需回查。教程项目保留为"练习册/参考答案"，不在其代码上继续开发。

| 阶段 | 内容 |
|---|---|
| 第 1 天 | 快速过 Astro 官方教程前半：环境搭建、创建页面、组件、布局 |
| 第 2-5 天 | 从零搭建自己的博客：项目骨架、BaseLayout、导航、Hero 首页雏形 |
| 第 6-7 天 | Content Collections、文章列表、详情页、标签（对照教程相应章节） |
| 第 8-10 天 | 项目页、关于页、Hero 完善、整体样式打磨 |
| 第 11 天 | GitHub Actions 部署上线 |
| 第 12-14 天 | 加分项（见第 8 节），收尾 |

辅导方式：开发者动手写代码，教练讲解概念、布置任务、review 代码、协助调试。
