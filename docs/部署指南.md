# 部署指南（GitHub Pages + 自定义域名与备案）

## 1. 部署架构

- **托管**：GitHub Pages（静态站，免费）
- **流水线**：GitHub Actions，push 到 `main` 分支自动构建发布
- **构建命令**：`npm run build`（含 Pagefind 搜索索引生成，工作流自动执行，无需额外配置）
- **工作流文件**：`.github/workflows/deploy.yml`（已建好，用的是 Astro 官方 `withastro/action@v3`）

## 2. 关键决策：仓库名必须叫 `用户名.github.io`

代码里有大量手写绝对路径（`/blog`、`/tags`、`/videos/hero.mp4`、`/favicon.png`、`/pagefind/...`）。
普通仓库名（如 `blog`）会把网站部署到 `用户名.github.io/blog/` 子路径，Astro 的 `base` 配置只处理自动生成的资源链接，手写路径会全部 404。

用 `用户名.github.io` 这个特殊仓库名，网站直接部署在根路径，现有代码零改动。

## 3. 部署步骤

### Step 1：创建 GitHub 仓库

1. 打开 https://github.com/new
2. Repository name 填 `你的用户名.github.io`（GitHub 会识别为特殊仓库并显示提示）
3. 选 **Public**；不勾选 README / .gitignore / license（保持空仓库）
4. 创建

### Step 2：写入站点地址

`astro.config.mjs`：

```js
// @ts-check
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://你的用户名.github.io',
});
```

### Step 3：提交并推送

```bash
git add -A
git commit -m "chore: 配置 GitHub Pages 部署"
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git branch -M main
git push -u origin main
```

（本地分支目前叫 `master`，`git branch -M main` 改名为 `main`，与 workflow 里的触发分支一致。）

### Step 4：开启 Pages

仓库页面 → **Settings → Pages → Source** 选 **GitHub Actions**（不是 Deploy from a branch）。

### Step 5：验证

- push 后到仓库 **Actions** 标签页看工作流跑通（build → deploy 两个绿灯）
- 访问 `https://你的用户名.github.io/`，对照本地 `npm run preview` 的效果逐项检查：
  - 样式正常（CSS 没 404）
  - Hero 视频播放、星空背景出现
  - 文章链接、标签、归档可点
  - Pagefind 搜索可用（线上是构建产物，索引在）
  - favicon 显示

## 4. 自定义域名与备案方案（浙江）

### 先明确规则

**是否需要 ICP 备案，取决于服务器在哪里，不取决于域名在哪里买：**

| 方案 | 服务器 | 需要备案吗 | 国内访问 |
|---|---|---|---|
| A. github.io 默认域名 | 境外（GitHub） | 不需要 | 可用，偶尔慢/不稳 |
| B. 自定义域名 → GitHub Pages | 境外（GitHub） | 不需要 ICP 备案* | 同 A |
| C. 自定义域名 → 国内托管（阿里云 OSS / 腾讯云 COS + CDN） | 境内 | **必须 ICP 备案** | 快且稳 |

\* 方案 B 的注意事项：域名在国内注册商（阿里云/腾讯云）购买只需**实名认证**（上传身份证，1-3 天），不需要备案；想完全免去实名环节可从境外注册商（Cloudflare / Namesilo）购买。

### 建议路线

**先 B 跑起来，有必要再迁 C。** 博客刚上线，访问量低，GitHub Pages 完全够用；等真的觉得国内访问慢了，再启动备案迁移（备案周期两三周，期间 GitHub Pages 继续服务，无缝衔接）。

### 方案 C：浙江 ICP 备案流程（需要时参考）

**前置条件：**

1. 域名：在国内注册商购买并完成实名认证，**域名持有者姓名须与备案主体（你本人）一致**
2. 国内服务器/托管：阿里云 OSS 静态网站托管 或 腾讯云 COS（静态博客不需要买云服务器），备案通过该服务商的备案系统提交
3. 证件：本人身份证；**非浙江身份证通常还需浙江省居住证**（以备案系统实际要求为准）

**流程（以阿里云为例，腾讯云类似）：**

1. 注册商处完成域名实名认证，等 2-3 天信息同步到工信部
2. 阿里云备案系统（App 或网页）填写主体信息和网站信息
   - 网站名称避开企业/行业词汇，个人站写"某某的个人主页"这类最稳
   - 人脸识别核验（阿里云 App 内完成，不用再对着幕布拍照）
3. 服务商初审：1-2 个工作日，会有电话核验（注意接 0571 等开头的外地号码）
4. 工信部短信核验：收到短信后 24 小时内到工信部官网完成验证
5. **浙江省通信管理局审核**：官方时限 20 个工作日，浙江实际一般 5-10 个工作日出结果
6. 备案号下发后：**必须挂在网站底部**（格式：`浙ICP备XXXXXXXX号`，链接到 beian.miit.gov.cn）——我们的 Footer 到时候加一行
7. **公安备案**：ICP 备案下来后 30 日内，到"全国互联网安全管理服务平台"（beian.gov.cn）再做一次公安备案，得到 `浙公网安备 XXXXX` 号，同样挂到页底

**费用参考：** 域名 .com 约 60-70 元/年（.cn 更便宜）；OSS/COS 静态托管按量计费，个人博客量级一个月几块钱；CDN 可选。

**注意：** 备案审核期间（新增网站备案）要求网站处于无法访问状态——这正是"先用 GitHub Pages 顶着"的另一个理由。政策细节各省管局会微调，提交前以备案系统内的最新提示为准。

### 方案 C：国内部署技术步骤（备案下来后）

本站是纯静态产物 `dist/`，迁移只动 CI 和云服务配置，**源码一行不用改**（当初坚持根路径部署的红利——没有任何子路径依赖）。

**一次性配置：**

1. OSS（阿里云）或 COS（腾讯云）建桶，开启**静态网站托管**，默认首页 `index.html`、404 页面 `404.html`
2. 绑定已备案域名，申请云厂商的**免费 SSL 证书**开启 HTTPS
3. （可选）开同厂商 CDN 加速，回源指向 OSS/COS
4. DNS 处把域名 CNAME 到 CDN/OSS 提供的地址
5. 云厂商控制台创建一对**子账号 AccessKey**（只授权该桶的读写权限，别用主账号 key），存进 GitHub 仓库的 **Settings → Secrets and variables → Actions**：`ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET`
6. 改 `.github/workflows/deploy.yml`：构建步骤不变，把"部署到 Pages"换成上传步骤。阿里云示例：

```yaml
      - name: 构建
        run: npm ci && npm run build

      - name: 上传到 OSS
        uses: manyuanrong/setup-ossutil@master
        with:
          endpoint: oss-cn-hangzhou.aliyuncs.com   # 桶所在地域
          access-key-id: ${{ secrets.ALIYUN_ACCESS_KEY_ID }}
          access-key-secret: ${{ secrets.ALIYUN_ACCESS_KEY_SECRET }}

      - run: ossutil cp -r -f -u dist/ oss://你的桶名/   # -u 上传时跳过未变化的文件
```

（腾讯云对应 `coscmd`，官方文档有 Actions 示例。）

**日常更新流程（迁移后）：对你完全不变**——

```
Obsidian 写文章 → git add -A → git commit → git push
                                                  ↓
                              Actions 自动构建 dist/ → 上传覆盖 OSS
                                                  ↓
                                        1-2 分钟后线上就是新版
```

唯一的新概念是 **CDN 缓存**：开了 CDN 后，边缘节点可能还缓存着旧文件，更新后有几分钟到几小时的延迟。两个应对：

- HTML 页面设短缓存（几分钟），图片/视频等静态资源设长缓存（它们文件名/内容基本不变）
- 或者在 CI 最后加一步调 CDN 的"刷新预热"API，push 后立即全量刷新（云厂商都有这个 API，需要时再加）

**双跑期建议**：迁移完成后 GitHub Pages 可以留着当备份——Actions 里保留原部署步骤，push 一次两边同时更新；国内域名走 OSS，`CyanSyl.github.io` 继续可用。

## 5. 常见问题

| 症状 | 原因 | 解法 |
|---|---|---|
| 线上页面无样式，控制台 CSS 404 | 仓库名不是 `用户名.github.io` 且没配 `base` | 按第 2 节换仓库名，或配置 `base` 并给手写路径加前缀（不推荐） |
| Actions 里 build 成功但网站 404 | Pages Source 没选 GitHub Actions | Settings → Pages → Source 改选 |
| push 后网站没更新 | 工作流没触发（分支名不对） | 确认本地分支已 `git branch -M main` 并推到 `main` |
| 搜索没结果 | Pagefind 索引未生成 | 确认构建命令是 `npm run build`（含 pagefind 步骤），workflows 默认执行它 |
