# 风格设计：月夜深蓝（Dark Theme）

- 日期：2026-10-22
- 状态：待实施（对应实施计划 Task 10 样式打磨）
- 设计目标：与首页 Hero 图（深蓝夜空 + 冷月，菈妮主题）形成一体感，避免内容区配色与 Hero 割裂

## 1. 设计理念

整张 Hero 大图像"流入"页面：页面底色取自夜空的深蓝黑，强调色取自月光的冷蓝。
文字与卡片层级参考 GitHub Dark 的成熟度——暗底上不刺眼、层级清晰。

## 2. 配色（CSS 变量，全部集中在 `:root`）

| 变量 | 值 | 用途 |
|---|---|---|
| `--color-bg` | `#0d1117` | 页面底色：深夜蓝黑（取自 GitHub Dark） |
| `--color-bg-card` | `#161b26` | 卡片底色：稍亮的蓝灰 |
| `--color-border` | `#2a3345` | 卡片/分隔线边框 |
| `--color-text` | `#e6e9f0` | 主文字：柔和灰白（不用纯白，防刺眼） |
| `--color-muted` | `#8b94a8` | 次要文字：灰蓝（日期、摘要、页脚） |
| `--color-accent` | `#7aa2f7` | 强调色：月光蓝（链接、悬停、点缀，取自 Tokyo Night） |
| `--max-width` | `720px` | 内容行宽（不变） |

注意：组件里现有的硬编码颜色（`#e5e7eb`、`#f3f4f6` 等）需全部替换为变量。

## 3. 排版

- 正文：17px / 行高 1.8，中文长文阅读舒适
- 标题层级：h1 28px / h2 22px / h3 18px，段间距加大
- 文章详情页：h2 上边距加大（2.5rem），代码块配深色底
- 行宽保持 720px

## 4. 组件规格

### 导航（Header）
- **玻璃态（参考 Fuwari 主题配方）**：60% 透明度深色底 + `backdrop-filter: blur(20px)` 强模糊 + 底部圆角（0 0 .75rem .75rem）+ 1px 细边 + 柔和投影
- 固定在顶部（`position: fixed`），滚动时悬浮于 Hero 之上，Hero 图透过导航形成磨砂玻璃质感
- 当前页面对应的导航项用强调色高亮
- 配套：`BaseLayout` 的 `main` 加 `padding-top: 56px` 给固定导航让位；首页 `.hero` 用 `margin-top: -56px` 延伸到导航底下

### Hero
- 底部加渐变过渡带：从透明渐变到 `--color-bg`，大图自然流入内容区
- 标语文字保持白色 + 文字阴影

### 卡片（PostCard / ProjectCard）
- 背景 `--color-bg-card`，圆角 8px，1px 边框 `--color-border`
- 悬停：上浮 2px（`transform: translateY(-2px)`）+ 边框变 `--color-accent`，过渡 0.2s

### 页脚（Footer）
- 顶部 1px `--color-border` 分隔线，文字用 `--color-muted`

### 滚动条
- 沿用已实现的自定义滚动条，滑块颜色改用 `--color-border` 系深色

## 5. 响应式检查点

- 手机视图（375px）：导航不挤压、Hero 文字不溢出、卡片单列排列
- 媒体查询断点：480px（导航间距）、636px（沿用教程习惯）

## 6. 参考标杆

- GitHub 深色模式：底色与文字层级
- Vercel 博客：深色极简卡片
- Tokyo Night 主题：月光蓝强调色

## 7. 实施清单

1. `global.css`：替换 `:root` 变量、正文排版参数、滚动条配色
2. `Header.astro`：固定悬浮 + 半透明毛玻璃 + 当前页高亮
3. `Footer.astro`：边框与文字色改变量
4. `PostCard.astro` / `ProjectCard.astro`：卡片化（背景、圆角、边框、悬停上浮）
5. `BlogPost.astro`：文章排版打磨（标题层级、段距、代码块）
6. `index.astro`：Hero 底部渐变过渡带
7. 各页面桌面/手机视图走查

## 8. 实施方式

### 分工

- 样式实现由教练（AI）完成（用户明确委托）
- 用户负责逐步验收：每步完成后在浏览器查看效果，确认或提出调整

### 顺序与原则：先地基，后组件，小步验证

按"变量 → 全局 → 组件 → 页面"的依赖顺序实施，**每完成一步立即验证**，而不是全部改完再看：

| 批次 | 内容 | 验证方式 |
|---|---|---|
| 第 1 批 | `global.css` 变量 + 排版 + 滚动条 | 刷新页面：全站立即变深色（变量的威力——组件里用变量的地方自动跟随）；`npx astro check` 无报错；提交 `style: 切换月夜深蓝配色与排版地基` |
| 第 2 批 | Header + Footer | 刷新：导航悬浮毛玻璃、各页面导航高亮正确；提交 `style: 导航与页脚深色化` |
| 第 3 批 | PostCard + ProjectCard | 刷新：列表页/项目页卡片化与悬停效果；提交 `style: 卡片组件深色化` |
| 第 4 批 | BlogPost + 首页 Hero 渐变带 | 打开一篇文章 + 首页滚动检查；提交 `style: 文章排版与 Hero 过渡` |
| 第 5 批 | 全面走查 | 逐页（`/`、`/blog`、文章详情、`/tags`、`/projects`、`/about`）× 桌面/手机视图逐项检查；问题逐个修；提交 `style: 响应式与整体打磨` |

### 验收标准（每批次通用）

- 浏览器实际效果符合本文档第 2-4 节规格
- `npx astro check` 与 `npm run build` 无报错
- 一个批次一个 commit，出问题可用 `git checkout -- <文件>` 单独回退该批次

### 调整机制

- 色值微调：只改 `global.css` 的 `:root` 变量，全站生效，无需动组件
- 用户对某批次效果不满意：描述问题 → 教练修改 → 重新验证，通过后再进下一批次
- 工具：浏览器开发者工具（F12）可实时试色，调好后回写到 CSS 文件
