# 样式实施记录

记录"月夜深蓝"主题实施过程中每批的改动与关键技术要点。设计规格见 `docs/风格设计.md`。

## 批次 1：配色与排版地基（commit `style: 切换月夜深蓝配色与排版地基`）

**改动文件：** `src/styles/global.css`（全文替换）

**改动内容：**
- `:root` 变量从浅色主题（白底黑字蓝链接）替换为月夜深蓝主题（`#0d1117` 底、`#e6e9f0` 字、`#7aa2f7` 强调色）
- 新增卡片底、边框两个变量
- 正文排版：17px / 行高 1.8
- 滚动条滑块颜色改用变量
- 新增 `html { scroll-behavior: smooth; }`（锚点跳转平滑滚动）

**要点：**
- **CSS 变量的威力**：只改 `:root` 一处，所有使用 `var(--color-*)` 的组件自动跟随。这就是"改色不改组件"的机制
- 组件里遗留的硬编码颜色（如 `#e5e7eb`）不会跟随变量，需要逐批替换——这正是后续批次的工作

## 批次 2：玻璃态导航 + 深色页脚（commit `style: 导航玻璃态（参考 Fuwari 配方）与页脚深色化`）

**改动文件：**
- `src/components/Header.astro`（全文重写）
- `src/components/Footer.astro`（边框色改变量）
- `src/layouts/BaseLayout.astro`（新增 `main { padding-top: 56px; }`）
- `src/pages/index.astro`（`.hero` 新增 `margin-top: -56px`）

**改动内容：**
- 导航栏改为玻璃态（参考 Fuwari 主题）：`rgba(13,17,23,0.6)` 半透底 + `backdrop-filter: blur(20px)` + 底部圆角 + 细边 + 投影
- 导航固定顶部（`position: fixed`），当前页面导航项用 `Astro.url.pathname` 判断并高亮
- 页脚边框色改为 `--color-border`

**要点：**
- **玻璃态配方** = 半透明背景（60% 透明度）+ 强背景模糊（blur 20px）。底层内容透过元素模糊显现，形成磨砂玻璃质感；`backdrop-filter` 只对元素"背后"的内容生效，不影响自身内容
- **固定导航的连锁改动**（典型牵一发动全身案例）：
  1. `position: fixed` 把导航移出文档流 → 正文会顶到导航底下
  2. 解法一：`main` 加 `padding-top` 给导航让位（内页需要）
  3. 解法二：首页 Hero 用负 `margin-top` 抵消，让图片延伸到导航底下（满屏效果需要）
- **当前页高亮的实现**：`Astro.url.pathname` 拿到当前路径，首页精确匹配 `/`，其余用 `startsWith` 前缀匹配（`/blog`、`/blog/xxx` 都算"文章"栏目）
- `-webkit-backdrop-filter` 前缀：Safari 兼容需要，写两遍是行业惯例

## 批次 3：卡片组件深色化（commit `style: 卡片组件深色化（修复标签白底）`）

**改动文件：**
- `src/components/PostCard.astro`（从"下划线列表项"改为卡片）
- `src/components/ProjectCard.astro`（卡片化 + 修复技术栈标签白底）

**改动内容：**
- 两种卡片统一规格：`--color-bg-card` 底 + 1px `--color-border` 边 + 8px 圆角
- 悬停效果：上浮 2px（`translateY(-2px)`）+ 边框变强调色，`transition` 0.2s
- 技术栈标签：`#f3f4f6` 硬编码白底 → `--color-bg` 深底 + `--color-border` 细边（修掉了暗色主题下的白底突兀问题）

**要点：**
- **硬编码颜色是主题切换的最大敌人**：批 1 换变量时组件自动跟随，凡是写死色值的地方（`#e5e7eb`、`#f3f4f6`）都会"漏网"，必须逐个揪出。排查方法：全局搜索 `#[0-9a-f]` 色值
- **`transition` 过渡动画**：`transition: transform 0.2s, border-color 0.2s` 声明"这两个属性变化时用 0.2 秒渐变"，悬停效果因此平滑而非跳变。`transform` 和颜色是最适合动画的属性（性能好，不触发重排）

## 批次 4：文章排版 + Hero 渐变带（commit `style: 文章排版打磨与 Hero 渐变过渡带`）

**改动文件：**
- `src/layouts/BlogPost.astro`（排版全面打磨）
- `src/pages/index.astro`（Hero 新增 `::after` 渐变带）

**改动内容：**
- 文章排版：标题层级（h1 28px/h2 22px/h3 18px）、h2 段前距 2.5rem、列表缩进、行内代码与代码块深色卡片化、引用块左侧强调色竖线
- Hero 底部加 30% 高度的渐变带（透明 → 页面底色），大图自然"流入"内容区

**要点：**
- **`:global()` 的用途**：组件 scoped 样式默认只管组件自己写的 HTML；Markdown 渲染出的正文（`<slot />` 里的内容）不带本组件的 scope 标记，必须用 `:global(h2)` 才能选中
- **`::after` 伪元素**：在元素内部末尾"凭空"插入一个盒子（`content: ''`），用来加装饰层而不污染 HTML。渐变带、角标、下划线动画都常这么做
- **`linear-gradient(to bottom, transparent, var(--color-bg))`**：从透明渐变到页面底色，两个面的交界处视觉融合。图片与页面衔接的常用手法
- 代码块 `overflow-x: auto`：代码过长时块内横向滚动，不撑破页面

## 补充：全文搜索（Pagefind）与标签筛选（commits `feat: Pagefind 全文搜索`、`feat: 文章列表页标签筛选栏`）

**改动文件：** `package.json`（build 加 pagefind 索引步骤）、`src/layouts/BlogPost.astro`（`data-pagefind-body`）、`src/layouts/BaseLayout.astro`（组件 UI 资源 + `<pagefind-modal>`）、`src/components/Header.astro`（`<pagefind-modal-trigger>`）、`src/pages/blog/index.astro`（筛选栏）

**要点：**
- **Pagefind 架构**：构建后扫描 dist 生成静态索引文件，搜索完全在浏览器本地进行，零后端。中文分词内置
- **`data-pagefind-body`**：标记"只索引这里"。加了它的页面才进索引，首页/关于页等自动排除
- **Component UI（1.5+）**：Web Components 形式的现成搜索 UI。`<pagefind-modal-trigger>`（按钮）+ `<pagefind-modal>`（弹窗）放哪都能用，自动按网站语言翻译
- **dev 模式的坑**：`/pagefind/*` 只在构建后存在于 dist，`astro dev` 下搜索按钮不渲染；测试用 `npm run build && npm run preview`
- **标签筛选的实现**：服务端把每篇文章的 tags 写进 `data-tags` 属性，客户端 JS 点击按钮时切换 `display`。数据在构建时固化，筛选是纯 DOM 操作——静态站"伪交互"的典型模式

## 补充：归档页（commit `feat: 归档页（按年份时间线分组）`）

**改动文件：** `src/pages/archive.astro`（新增）、`src/components/Header.astro`（导航加"归档"）、`src/pages/index.astro` 与 `src/pages/blog/index.astro`（修复 `<script>` 里 TS 类型报错）

**要点：**
- **归档页结构**：`getCollection` 取文 → 按 `date.getFullYear()` 用 `Map` 分组 → 年份倒序渲染；每行是"MM-DD + 标题"的整行 `<a>`

## 补充：文章页增强（commit `feat: 文章页增强——目录 TOC、上下篇导航、字数与阅读时长、代码块复制按钮`）

**改动文件：** `src/layouts/BlogPost.astro`（TOC/上下篇/meta/复制按钮）、`src/pages/blog/[...slug].astro`（数据准备）

**要点：**
- **TOC 目录**：`render(post)` 除了 `Content` 还返回 `headings`（每个标题的 depth/slug/text）；Astro 会自动给正文 h2/h3 生成 `id`，所以目录链接 `#slug` 直接可用，中文标题也没问题。筛 depth 2/3，右侧 sticky 栏（`position: sticky; top: 5rem`），窄屏（<1024px）整体隐藏
- **scroll-spy 高亮**：`IntersectionObserver` 监听正文标题，`rootMargin: '0px 0px -70% 0px'` 让"标题到达视口上部 30%"才算进入，进入时给对应目录项加 `.active`
- **上下篇导航**：`getStaticPaths` 里把 posts 排序后用下标取 `posts[i-1]`/`posts[i+1]` 当 props 传入，布局里 `?? null` 处理边界（最新/最早一篇只有单侧链接）
- **字数统计**：`post.body` 拿到 Markdown 原文，正则去掉代码块和标记符号，中文字符（`[一-鿿]`）+ 英文单词分开计数再相加；阅读时长 = 字数 ÷ 400（中文阅读速度经验值）
- **代码复制按钮**：客户端 JS 给每个 `pre` 动态 `appendChild` 一个按钮，`navigator.clipboard.writeText` 写剪贴板；CSS 上按钮 `opacity: 0`、`pre:hover` 时显现（`pre` 需 `position: relative` 作为定位基准）
- **验证技巧**：新建临时 md 文章（含 h2/h3/代码块）→ build → 直接 grep `dist/` 产物 HTML 确认渲染结果 → 删掉临时文再 build 一次。验证组件不需要改用户的文章

## 补充：Hero 银河视差与全站动效（commit `feat: Hero 银河视差与入场动画、全站滚动浮现、文章页演示文`）

**改动文件：** `src/pages/index.astro`（视频视差、入场动画）、`src/styles/global.css`（`.reveal`）、`src/layouts/BaseLayout.astro`（页面淡入 + 滚动浮现脚本）、`src/content/blog/demo-features.md`（演示文）

**要点：**
- **背景视差的关键技巧**：要平移一个 `object-fit: cover` 铺满的元素，必须先 `scale(1.06)` 放大，否则平移会露出边缘。各层系数：视频 0.3（最远）→ 远星 0.4 → 标语 0.7 → 近星 1.2，系数差制造纵深
- **入场动画与视差共存**：`@keyframes rise` 只在 `from` 里写 `transform`，`to` 不写——动画结束后 transform 回落到基础样式里的视差平移值，两者不打架
- **滚动浮现**：`.reveal`（opacity 0 + 下移 16px）→ IntersectionObserver 命中后加 `.visible`；`transitionDelay` 按元素序号错开 60ms 形成梯队，浮现完 `setTimeout` 清零延迟（否则 hover 过渡也被延迟）
- **所有动效都尊重 `prefers-reduced-motion`**：CSS 媒体查询 + JS 的 `matchMedia` 双管齐下
- **页面切换动效没用 Astro ClientRouter**：它要求所有 `<script>` 改包 `astro:page-load` 事件，现有脚本多、改造成本大；用 `main` 的 0.4s 淡入替代，零风险

## 补充：内页背景星空（commit `feat: 内页背景星空——微闪星星与偶发流星`）

**改动文件：** `src/components/Starfield.astro`（新增）、`src/layouts/BaseLayout.astro`（引入 + main 垫层级）、`src/components/Footer.astro`（垫层级）；另 `revert: 取消 Hero 视频背景跟随鼠标`（用户要求撤回）

**要点：**
- **结构**：一个 `position: fixed` 的 `<canvas>` 铺满视口，`z-index: 0`；`main`/`footer` 垫 `position: relative; z-index: 1` 让内容压在星空上。body 的不透明底色在最底层，canvas 在其上、内容之下——三层关系是核心
- **首页排除**：`Astro.url.pathname === '/'` 时不渲染组件（首页 Hero 已经有视频+星星+雾）。注意脚本仍会被打包进首页的共享 chunk，但 `getElementById` 拿不到 canvas 就退出，零开销
- **Canvas 动画循环**：`requestAnimationFrame` 每帧 `clearRect` 清屏重绘；`dt`（两帧时间差）驱动位移，保证不同刷新率下速度一致；`dpr`（devicePixelRatio）处理高分屏模糊
- **流星画法**：头 = 一个点，尾 = 沿速度反方向拉一条 `createLinearGradient` 渐隐线；生命周期到点从数组 filter 掉
- **星星闪烁**：亮度 = 基础值 + `sin(时间 × 速度 + 相位)` × 幅度，每颗星参数随机错开
- **性能**：标签页 `visibilitychange` 隐藏时 `cancelAnimationFrame` 暂停；`prefers-reduced-motion` 时只画一帧静态星空

## 补充：内页毛玻璃面板（commit `feat: 内页中栏毛玻璃面板，与星空背景形成层级区分`）

**改动文件：** `src/layouts/BaseLayout.astro`（panel 包裹 + `wide` prop）、`src/layouts/BlogPost.astro`（传 `wide`）

**要点：**
- **层级设计**：星空 canvas（底层）→ 毛玻璃板 `rgba(13,17,23,0.75)` + `blur(8px)`（中层，星光柔化透出）→ 文字/卡片（顶层）。参考站（Hexo Fluid 系）的中栏层级就是这么来的
- **宽度策略**：不用 `fit-content` 收缩包裹（grid 子元素在 shrink-to-fit 下宽度计算有坑），改用显式 `max-width` + `wide` prop 区分——普通内页 720+2rem，文章页有 TOC 时 720+260+2rem，由 BlogPost 根据 `toc.length` 自动传
- **`width: calc(100% - 2rem)` + `max-width` 组合**：宽屏被 max-width 限制居中，窄屏自动收窄并保留 1rem 两侧留白（单纯 max-width + auto margin 在窄屏会贴边）
- **首页不包**：`isHome` 判断与 Starfield 共用，Hero 保持全屏出血
- **`backdrop-filter` 的副作用**：会让元素成为 fixed 后代的包含块——本站面板内没有 fixed 元素，无碍，但以后往面板里加 fixed 定位的东西要注意

## 补充：夜空重制与面板层级修正（commit `style: 夜空重制——渐变天空、星云、月亮、多彩星星；面板调亮拉开层级`）

**问题：** 用户反馈初版夜空是"深灰墙 + 白点"没有夜空感，且面板色 `rgba(13,17,23,0.75)` 与底色过于接近，层级出不来。

**改动文件：** `src/components/Starfield.astro`（天空/月亮/星星）、`src/layouts/BaseLayout.astro`（面板色）

**要点：**
- **夜空纵深三件套**：CSS 渐变天空（天顶 `#04060e` → 地平线 `#131a36`）+ 两片低透明度 radial-gradient 星云雾（蓝/紫）+ 月亮（canvas 绘制：外层光晕径向渐变 + 月盘偏心径向渐变模拟明暗面）。全画在 canvas 的 CSS background 和每帧绘制里，零图片资源
- **星星层次**：数量 70→120，半径 0.4~1.7px 拉开大小差距，12% 暖色（`#ffe9c8`）+ 冷白/淡蓝混合——真实星空的颜色和亮度就是不均匀的
- **面板层级**：`rgba(24,30,46,0.82)`（比夜空亮、偏蓝）+ 更深的投影——"抬起的中层"必须比底层亮或更实，同色系不同明度是同色搭配的常规解法
- **教训**：暗色主题里做层级，明度差要比想象中大（0.75 透明度的同底色 ≈ 没有层级）
